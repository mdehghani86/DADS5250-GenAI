Setting Your DeepSeek API Key in Jupyter
For students running the labs on DeepSeek. Two minutes, once per session, or once per computer if you prefer. In Google Colab you would use the key sidebar; on your own Jupyter there are no Colab Secrets, so you set the key like this instead.
Your key is a password. Never paste it into a notebook cell you will save or submit, never print it in output, and never commit it to GitHub. The pattern below keeps the key out of your notebook file entirely.
Fastest check: open Lab 0 in Colab and press Run All. It verifies your key end to end in two minutes, nothing to copy.
Step 1. Get a DeepSeek key

Create an account at platform.deepseek.com (email or Google sign in), add a small credit (a few dollars covers the whole semester), and create a key under API Keys. Copy it right away, it is shown only once.

Step 2. Run this cell first, every session

Add this as the first cell you run. The first line tells the course toolkit to use DeepSeek; the second asks for your key with a hidden prompt, so the key never appears on screen or inside the saved notebook:

import os, getpass
os.environ["LLM_PROVIDER"] = "deepseek"
os.environ["DEEPSEEK_API_KEY"] = getpass.getpass("Paste your DeepSeek API key: ").strip()
import os, getpass os.environ["LLM_PROVIDER"] = "deepseek" os.environ["DEEPSEEK_API_KEY"] = getpass.getpass("Paste your DeepSeek API key: ").strip()

The .strip() matters: keys copied on Windows often carry an invisible space or line ending, which makes a valid key fail. When the prompt appears, paste the key and press Enter. Nothing is displayed, that is the point.

Prefer to set it once per computer? You can store the key on your computer so every notebook finds it automatically and you never type it again. It takes three steps.

 Watch the 1 minute walkthrough: setting your key once, on macOS and Windows

On macOS or Linux:

  1. Open the Terminal app.
  2. Copy the two lines below, replace the placeholder with your real key (keep the quotes), paste into Terminal, and press Enter. They save your settings into a file called ~/.zshrc that runs every time a terminal opens:
echo 'export LLM_PROVIDER="deepseek"' >> ~/.zshrc
echo 'export DEEPSEEK_API_KEY="sk-PASTE-YOUR-KEY-HERE"' >> ~/.zshrc
echo 'export LLM_PROVIDER="deepseek"' >> ~/.zshrc echo 'export DEEPSEEK_API_KEY="sk-PASTE-YOUR-KEY-HERE"' >> ~/.zshrc
  1. Close Terminal, open a new one, and check it worked. This should print your key:
echo $DEEPSEEK_API_KEY
echo $DEEPSEEK_API_KEY

On Windows:

  1. Open PowerShell (press the Windows key, type powershell, press Enter).
  2. Run these two lines once, with your real key in place of the placeholder (keep the quotes):
setx LLM_PROVIDER "deepseek"
setx DEEPSEEK_API_KEY "sk-PASTE-YOUR-KEY-HERE"
setx LLM_PROVIDER "deepseek" setx DEEPSEEK_API_KEY "sk-PASTE-YOUR-KEY-HERE"
  1. Close PowerShell, open a NEW one, and check it worked. This should print your key:
echo $env:DEEPSEEK_API_KEY
echo $env:DEEPSEEK_API_KEY
The one rule that trips everyone: the key only reaches programs started AFTER you set it. So close Jupyter (and Anaconda Navigator, if you use it) and start it again from a fresh terminal. If a notebook still says the key is not found, this is almost always why.
Step 3. Verify

Run the lab's own setup and API check cells. You should see deepseek ready | model: deepseek-flash | status: connected. Or simply open Lab 0 (the green button at the top) and Run All: it checks everything and tells you the fix if something is off.

Step 4. One more key for the embeddings labs (M01 Lab 2, M05, M10)

DeepSeek does not offer embeddings, so three labs use a second free key from Alibaba Model Studio (Singapore): create an account at modelstudio.console.alibabacloud.com, make a key, and add it the same way as the others, named QWEN_API_KEY. The toolkit routes embeddings to it automatically. Without it, every chat lab still works; only those three labs will ask for it.

os.environ["QWEN_API_KEY"] = getpass.getpass("Paste your Qwen key: ").strip()
os.environ["QWEN_API_KEY"] = getpass.getpass("Paste your Qwen key: ").strip()
If something fails
"DEEPSEEK_API_KEY not found" The key cell has not run in this session. Run the Step 2 cell first, then the setup cell, in that order.
401 or "invalid key", but the key looks right Almost always a trailing space or a Windows line ending picked up during copy paste. The .strip() in the Step 2 cell removes it; if you set the key elsewhere, retype the last few characters by hand.
It worked, then stopped after a restart Restarting the kernel clears everything the Step 2 cell set. That is normal: run the key cell again. If this annoys you, use the set once per computer option above and it survives restarts.
Labs still call OpenAI instead of DeepSeek The LLM_PROVIDER line must run BEFORE the setup cell. Set it in the first cell, restart the kernel, and run top to bottom. Lab 0's section 4 shows whether the runtime can actually see it.
Embeddings cells say a key is missing Expected until you add QWEN_API_KEY (Step 4). Only M01 Lab 2, M05 and M10 need it.
Using OpenAI instead? Then you need none of the provider lines above: just set OPENAI_API_KEY the same way (hidden prompt or shell profile) and skip Step 4. The toolkit defaults to OpenAI whenever LLM_PROVIDER is not set.
Never do these. Do not write the key directly in a cell, do not print(os.environ["DEEPSEEK_API_KEY"]), do not screenshot or screen share with the key visible, and do not push a notebook whose output contains any part of a key. If a key leaks, revoke it on the provider dashboard and create a new one.
