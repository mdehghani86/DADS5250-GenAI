Setting Your API Key in Jupyter
Two minutes, once per session. In Google Colab you would use the key sidebar; on your own Jupyter there are no Colab Secrets, so you set the key like this instead.
Your key is a password. Never paste it into a notebook cell you will save or submit, never print it in output, and never commit it to GitHub. The pattern below keeps the key out of your notebook file entirely.
Step 1. Get a key

Create one at platform.openai.com under API keys. Copy it right away, it is shown only once. If OpenAI is not available in your country, see the last section of this page.

Step 2. Run this cell first, every session

Add this as the first cell you run. It asks for the key with a hidden prompt, so the key never appears on screen or inside the saved notebook:

import os, getpass
os.environ["OPENAI_API_KEY"] = getpass.getpass("Paste your OpenAI API key: ").strip()

The .strip() matters: keys copied on Windows often carry an invisible space or line ending, which makes a valid key fail. When the prompt appears, paste the key and press Enter. Nothing is displayed, that is the point.

Prefer to set it once per computer? Put the key in your shell profile instead, then you never type it again and every lab finds it automatically:

# macOS or Linux: add to ~/.zshrc, then restart the terminal
export OPENAI_API_KEY="sk-PASTE-YOUR-KEY-HERE"

# Windows PowerShell: run once, then reopen Jupyter
setx OPENAI_API_KEY "sk-PASTE-YOUR-KEY-HERE"
Step 3. Verify

Now run the lab's own setup and API check cells. You should see OpenAI ready | model: ... | status: connected. If the setup cell shows a hidden prompt instead, that is the same mechanism offering you a second chance to paste the key.

If something fails
"OPENAI_API_KEY not found" The key cell has not run in this session. Run the Step 2 cell first, then the setup cell, in that order.
401 or "invalid key", but the key looks right Almost always a trailing space or a Windows line ending picked up during copy paste. The .strip() in the Step 2 cell removes it; if you set the key elsewhere, retype the last few characters by hand.
It worked, then stopped after a restart Restarting the kernel clears everything the Step 2 cell set. That is normal: run the key cell again. If this annoys you, use the shell profile option in Step 2 and it survives restarts.
Provider set, but labs still call OpenAI The provider choice below is read when the setup cell runs its imports. Set it in the first cell, before the setup cell, then restart the kernel and run top to bottom.
No OpenAI access in your country?

The course toolkit (dads5250 version 0.3.0 and later) supports DeepSeek as a drop in provider. Make your first cell this instead, and the labs run unchanged:

import os, getpass
os.environ["LLM_PROVIDER"] = "deepseek"
os.environ["DEEPSEEK_API_KEY"] = getpass.getpass("Paste your DeepSeek key: ").strip()

Account setup, the optional Qwen key for the embeddings labs, and troubleshooting for this path are in the guide labs/ALTERNATIVE_PROVIDERS.md in the course GitHub repository. Students with OpenAI access should ignore this section, the default needs no provider line at all.

Never do these. Do not write the key directly in a cell, do not print(os.environ["OPENAI_API_KEY"]), do not screenshot or screen share with the key visible, and do not push a notebook whose output contains any part of a key. If a key leaks, revoke it on the provider dashboard and create a new one.
